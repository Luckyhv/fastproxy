# Deploying fastproxy on two origins

Target layout:

```text
viewer -> Cloudflare CDN + Load Balancer -> Caddy :443 -> fastproxy 127.0.0.1:3847
```

Use the same app config, `SECRET_KEY`, and Cloudflare origin certificate on both
servers. Cloudflare should do the traffic split; each Caddy only proxies to its
local fastproxy process.

Files in this folder:

| file | purpose |
| --- | --- |
| `Caddyfile` | Caddy reverse proxy for each origin |
| `fastproxy.service` | systemd unit for the Go app |
| `fastproxy.env.sample` | production environment template |
| `99-fastproxy.conf` | kernel/file-descriptor tuning for streaming load |

## 1. Pick the two origins

Use two Ubuntu 24.04 VPSs with strong bandwidth. For video proxying, network is
usually the real limit before CPU.

Recommended starting size per server:

- 2-4 vCPU
- 4-8 GB RAM
- 1 Gbps+ port if available
- Same region if your viewers are mostly in one country, or two nearby regions
  if you want better resilience

Examples used below:

```text
proxy.example.com       public hostname
203.0.113.10            origin A
203.0.113.11            origin B
/opt/fastproxy          app directory
/etc/fastproxy/fastproxy.env
```

## 2. Install Go and build

Run on both servers:

```sh
sudo apt update
sudo apt install -y curl git ca-certificates tar

cd /tmp
curl -LO https://go.dev/dl/go1.24.4.linux-amd64.tar.gz
sudo rm -rf /usr/local/go
sudo tar -C /usr/local -xzf go1.24.4.linux-amd64.tar.gz
echo 'export PATH=/usr/local/go/bin:$PATH' >> ~/.bashrc
export PATH=/usr/local/go/bin:$PATH

sudo useradd --system --home /opt/fastproxy --shell /usr/sbin/nologin fastproxy
sudo mkdir -p /opt/fastproxy /etc/fastproxy
sudo chown fastproxy:fastproxy /opt/fastproxy

git clone https://github.com/Luckyhv/fastproxy.git /tmp/fastproxy
cd /tmp/fastproxy
go build -trimpath -ldflags="-s -w" -o fastproxy .

sudo install -o fastproxy -g fastproxy -m 0755 fastproxy /opt/fastproxy/fastproxy
```

## 3. Configure fastproxy

Run on both servers. Keep `SECRET_KEY` identical or tokens generated by your
frontend will only work on one origin.

```sh
sudo tee /etc/fastproxy/fastproxy.env >/dev/null <<'EOF'
PORT=3847
BIND_ADDR=127.0.0.1
SECRET_KEY=change-me-use-the-same-value-on-both-servers

# Frontend domains allowed to embed/use the proxy. Subdomains are included.
# Empty = open, which is useful for testing but not for production.
ALLOWED_ORIGINS=yourfrontend.com,localhost



# Optional knobs:
# MAX_CONCURRENT=0
# UPSTREAM_PROXY=
# UPSTREAM_PROXY_DOMAINS=
# INSECURE_TLS=0
# ALLOW_RAW_URL=1
EOF
sudo chmod 640 /etc/fastproxy/fastproxy.env
sudo chown root:fastproxy /etc/fastproxy/fastproxy.env
```

## 4. Install the service and kernel tuning

Run from the cloned repo on both servers:

```sh
cd /tmp/fastproxy
sudo cp deploy/99-fastproxy.conf /etc/sysctl.d/99-fastproxy.conf
sudo sysctl --system

sudo cp deploy/fastproxy.service /etc/systemd/system/fastproxy.service
sudo systemctl daemon-reload
sudo systemctl enable --now fastproxy
sudo systemctl status fastproxy

curl -i http://127.0.0.1:3847/health
```

Expected health output: `HTTP/1.1 200 OK` and body `ok`.

## 5. Install Caddy

Run on both servers:

```sh
sudo apt install -y debian-keyring debian-archive-keyring apt-transport-https curl
curl -1sLf 'https://dl.cloudsmith.io/public/caddy/stable/gpg.key' | sudo gpg --dearmor -o /usr/share/keyrings/caddy-stable-archive-keyring.gpg
curl -1sLf 'https://dl.cloudsmith.io/public/caddy/stable/debian.deb.txt' | sudo tee /etc/apt/sources.list.d/caddy-stable.list
sudo apt update
sudo apt install -y caddy
```

## 6. Cloudflare origin certificate

In Cloudflare:

1. Go to **SSL/TLS -> Overview** and set **Full (strict)**.
2. Go to **SSL/TLS -> Origin Server -> Create Certificate**.
3. Include `proxy.example.com` as a hostname.
4. Save the certificate and private key on both servers:

```sh
sudo mkdir -p /etc/ssl/cloudflare
sudo nano /etc/ssl/cloudflare/cert.pem
sudo nano /etc/ssl/cloudflare/key.pem
sudo chmod 640 /etc/ssl/cloudflare/cert.pem /etc/ssl/cloudflare/key.pem
sudo chown root:caddy /etc/ssl/cloudflare/cert.pem /etc/ssl/cloudflare/key.pem
```

Install the Caddyfile on both servers:

```sh
cd /tmp/fastproxy
sudo cp deploy/Caddyfile /etc/caddy/Caddyfile
sudo systemctl edit caddy
```

Paste:

```ini
[Service]
Environment=PROXY_HOST=proxy.example.com
```

Then validate and restart:

```sh
sudo caddy validate --config /etc/caddy/Caddyfile --adapter caddyfile
sudo systemctl restart caddy
sudo systemctl status caddy
```

## 7. Firewall the origins

Only Cloudflare should reach ports 80/443. SSH stays open. Run on both servers:

```sh
sudo apt install -y ufw
sudo ufw allow OpenSSH
for ip in $(curl -s https://www.cloudflare.com/ips-v4); do
  sudo ufw allow from "$ip" to any port 80,443 proto tcp
done
for ip in $(curl -s https://www.cloudflare.com/ips-v6); do
  sudo ufw allow from "$ip" to any port 80,443 proto tcp
done
sudo ufw default deny incoming
sudo ufw default allow outgoing
sudo ufw enable
sudo ufw status numbered
```

## 8. Create the Cloudflare load balancer

Cloudflare Load Balancing is a paid add-on. It is the cleanest way to split
traffic and fail over automatically.

Create:

1. **Monitor**
   - Type: `HTTPS`
   - Path: `/health`
   - Port: `443`
   - Expected body: `ok`
   - Host header: `proxy.example.com`
2. **Pool**
   - Name: `fastproxy-origins`
   - Origin A: `203.0.113.10`, enabled, weight `1`
   - Origin B: `203.0.113.11`, enabled, weight `1`
   - Attach the monitor above
   - Endpoint steering: **Least Outstanding Requests** when available
3. **Load Balancer**
   - Hostname: `proxy.example.com`
   - Default pool: `fastproxy-origins`
   - Steering: use **Least Outstanding Requests** if your plan exposes it;
     otherwise use random/weighted steering with equal weights.
   - Proxy status: proxied/orange cloud

For video, least-outstanding-requests is usually better than round-robin because
one request can stay open for a long stream. If one server gets more active
streams, new requests drift toward the other server.

No paid Load Balancing yet? Add two proxied `A` records for the same hostname as
a temporary split:

```text
proxy.example.com -> 203.0.113.10 proxied
proxy.example.com -> 203.0.113.11 proxied
```

That can distribute traffic, but it does not give you proper health-based
failover. Treat it as a temporary learning step, not the final setup.

## 9. Add Cloudflare cache rules

fastproxy already sends cache headers:

- media segments/files: long immutable cache
- VOD/master playlists: short browser cache, longer edge cache
- live playlists: tiny edge cache
- errors and partial 206 responses: no-store

Because many proxy URLs are extensionless, add a Cache Rule so Cloudflare treats
the proxy paths as eligible for cache and then respects the app's headers:

Rule name: `fastproxy media cache`

Expression:

```text
(http.host eq "proxy.example.com" and starts_with(http.request.uri.path, "/stream/"))
or (http.host eq "proxy.example.com" and starts_with(http.request.uri.path, "/hls/"))
or (http.host eq "proxy.example.com" and starts_with(http.request.uri.path, "/m3u8/"))
```

Settings:

- Cache eligibility: **Eligible for cache**
- Edge TTL: **Use cache-control header if present, bypass cache if not**
- Browser TTL: **Respect origin headers**

Optional but recommended:

- Enable **Tiered Cache** for better cache hit ratio across Cloudflare data
  centers.
- Do not add Caddy disk caching until you have measured a need. Cloudflare should
  be the cache layer; Caddy should stay a thin streaming reverse proxy.

## 10. Test

From your laptop:

```sh
curl -i https://proxy.example.com/health
curl -I https://proxy.example.com/
```

Expected:

- `/health` returns `200` and `ok`
- `/` returns `400`, `403`, or similar app-level rejection, which still proves
  Cloudflare -> Caddy -> fastproxy is working

Check which origin served a request:

```sh
sudo journalctl -u fastproxy -f
```

## Updating both origins

Run on each server:

```sh
cd /tmp/fastproxy
git pull
go build -trimpath -ldflags="-s -w" -o fastproxy .
sudo install -o fastproxy -g fastproxy -m 0755 fastproxy /opt/fastproxy/fastproxy
sudo systemctl restart fastproxy
```

For zero-ish downtime, update one server, wait until Cloudflare marks it healthy,
then update the other.

## Useful checks

```sh
systemctl status fastproxy caddy
journalctl -u fastproxy -n 100 --no-pager
journalctl -u caddy -n 100 --no-pager
ss -ltnp
curl -I http://127.0.0.1:3847/health
curl -Ik https://proxy.example.com/health
```

Common Cloudflare errors:

- `521`: Caddy is down, firewall is blocking Cloudflare, or the origin is not
  listening on 443.
- `525/526`: Cloudflare SSL mode/certificate mismatch. Use Full (strict) with a
  valid Cloudflare origin certificate for `proxy.example.com`.
- `CF-Cache-Status: DYNAMIC` on media: the cache rule is missing or the response
  was intentionally not cacheable, such as `206`, an error, or `no-store`.
